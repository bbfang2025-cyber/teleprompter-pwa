# 画幅与录像验收

首次打开默认固定 9:16。相机源比例有差异时，竖版预览及成片裁切铺满，横源做横版时优先保留边缘。测试所用手机环境是 Android 15 AVD 里的 Chrome 124，另有桌面 Chrome 的可控摄像头样本。设备特定的原生相机视野由 iPhone 实体机验收。

| 用户场景 | 可能的问题 | 发布前验收 |
| --- | --- | --- |
| 1. 第一次打开就竖拿开拍，也有人一进网址就横拿 | 默认被浏览器的采集比例或页面方向改变 | 用横竖两种视口检查初始状态固定为 9:16，再选择跟随手机并验证刷新后仍生效 |
| 2. Safari 交付 3:4 相机画面 | 预览标签显示 9:16，画面实际仍是有黑边的 3:4 | 3:4 测试源采样竖屏预览上下边缘，并解码 MP4/WebM 的 9:16 成片。另验交叉方向铺满、横源拍横版保留四角 |
| 3. 练习时单手反复按画幅键，想固定一个比例 | 频繁重开摄像头或切回错误比例 | 连按五次保持同一摄像头轨道，刷新后验证固定模式与跟随模式各自可恢复 |
| 4. 倒计时或开拍后才把手机转过去 | 旧方向继续开拍，或录制混入两个方向 | 倒计时取消并提示重开，录制时结束当前片段，重拍恢复新方向 |
| 5. 第一次用时拒绝麦克风，或麦克风被系统打断 | 默默录成无声，或页面卡住 | 拒绝权限进入提示，重试恢复；模拟音轨中断并保留已录数据 |
| 6. 在微信里点开，先关提示、用无相机模式排稿 | 不授权就无法使用提词器，重开丢稿 | 微信提示可关闭，纯提词能新建长稿；刷新检查多行文字和表情完整 |
| 7. 录一段 30 秒口播，中间暂停一下 | 时间轴变长、不能 seek，尾部有声无画面 | 播放与文件两层验证，FFmpeg 对尾部解码；注入异常时钟和音画长度不一致的样本 |
| 8. 手机切后台、相机断流、卡在旧帧 | 页面继续录到黑屏或占住摄像头 | 模拟切后台、冻结视频帧回调，验证结束录像、可回看且轨道释放 |
| 9. 回看点翻转，取消又重做，然后选下载或系统分享 | 文件和回看的方向不同，或取消后无法保存 | 测镜像左右像素、四角、音轨、取消与恢复；Android 验证下载文件与系统面板 |
| 10. 320px 小屏横竖来回，拖框、点调速 | 盖住快门或页面跟着误滚 | 320px 触控、旋转后控件范围、独立保存横竖屏位置；Android 实拖与实录 |

`node tests/webm-duration.cjs` 核对时钟、时长和音画尾部。安装 Playwright 后，`node tests/browser.cjs` 执行浏览器回归，`--case=repeatSwitches` 与 `--case=draftRecovery` 可单独复现两项流程。发布后另查正式站版本和原生安卓 Chrome 的录像、回看、翻转和下载。

iPhone 的判断标准是同一距离、同一场景下比较取景边缘，而非只比较头部在两个取景框里的大小。Safari 提供的源画幅、分辨率和原生相机的智能构图仍可能不同。

发布复核曾发现 HTML 已更新而版本 JSON 仍读到旧值。现固定主页面和版本文件的 EdgeOne 缓存策略，并在自动更新与手动检查中忽略低于当前版的构建号。单独运行 `--case=staleUpdate` 可验证旧 CDN 响应不会回退新版页面，较新的版本仍能触发刷新。

`--case=framing` 与 `--case=framingWebm` 对竖屏视口里切换横屏后的截图和下载文件进行像素检查。验收时分别检查固定画幅、跟随手机，以及实际横拿后的取景。相机只交付竖向源时，居中裁出的横屏画面会舍去一部分上下内容。iPhone 17 原生相机的 Center Stage 使用设备专用接口，网页取景以 Safari 实际交付的画面为准。

v1.3.4 用 `--case=quality` 检查真实编码后的原片和镜像文件都是 1080×1920、有音轨、回看显示导出分辨率，并验证摄像头拒绝 1080p 与 720p 请求时可恢复取景。测试源为 1440×1920 的可控画面，Safari 真机的可用分辨率以浏览器交付的画面为准。
